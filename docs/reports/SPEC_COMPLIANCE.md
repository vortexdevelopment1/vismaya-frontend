## 2. Legacy Phase 1 PRD vs. Master Spec v2.0 Evolution

The frontend was originally scaffolded against the older Phase 1 PRD. The table below traces each legacy concept to its current status under Master Spec v2.0:

| Feature / Pattern | Phase 1 PRD Behavior | Master Spec v2.0 Rule | Status in Codebase |
|---|---|---|---|
| **Public Casting-Call Browsing** | Anyone could browse open casting calls anonymously on public landing page. | **DROPPED:** Logged-out users must be redirected to `/login` (Master Spec §3, §4). | **FIXED:** `/opportunities` enforces login redirect (`[opportunityId]/page.js:40-44`). |
| **Admin Curated Shortlist** | Admin manually created talent shortlists for recruiters. | **DROPPED:** Organizations curate their own private project shortlists and request auditions directly (Master Spec §30, §31). | **FIXED:** Shortlists are recruiter-managed; admin only moderates auditions and reviews new briefs. |
| **Success Commission** | Platform charged a percentage commission on talent bookings. | **DROPPED:** Strict zero-commission policy; platform monetises solely via credit packs and registration fees (Master Spec §28). | **FIXED:** No commission tracking or booking fee calculators exist. |
| **SMS / WhatsApp Alerts** | Recruiter and talent notified via third-party SMS/WhatsApp gateway. | **DROPPED:** Email and in-app notifications only (Master Spec §37). | **FIXED:** Backend and frontend notify via Nodemailer and in-app Notification center. |
| **Admin System Broadcasts** | Admin broadcast banners sent to all user dashboards. | **RETAINED IN SPEC (§44), BUT NOT IN BACKEND:** | **HANDLED:** Frontend shows honest unavailable state in real mode (BK-005). |
| **Recruiter Star Ratings** | Recruiters could leave public star ratings on talent profiles. | **DROPPED:** Subjective ratings removed to protect talent privacy and prevent bias (Master Spec §39). | **FIXED:** No star rating components or schema fields exist. |
| **Audition Clip at Apply Time** | Talent uploaded audition video upon initial application. | **DROPPED:** Application is strictly profile-only; audition self-tapes are submitted only upon formal recruiter invitation (Master Spec §32, §33). | **FIXED:** Two-stage application -> audition workflow strictly enforced. |

## 3. Product Decision Required (Document Contradictions)

The audit revealed the following direct contradictions between **Master Spec v2.0** and **Round 28 Decisions**. Per project rules, these are flagged as **NEEDS PRODUCT DECISION** without silent assumption:

### 1. Opportunity Detail: Production Company & Remuneration Visibility
- **Master Spec v2.0 §31:** Mandates strict anonymity. Remuneration and Production Company name/logo must remain hidden until an applicant is shortlisted or selected.
- **Round 28 Decisions (Item 5):** Lists Remuneration and Role Category as public parameters on the opportunity brief.
- **Current Code Decision:** Frontend follows Master Spec v2.0 §31 (masks company as "Verified Production Studio" and remuneration as "Standard Scale / Project Disclosed").
- **Product Action Required:** Product Management must confirm whether budget/remuneration and company branding should be revealed to logged-in talent before application.

### 2. Audition Pipeline: Admin Relay vs. Admin Approval
- **Master Spec v2.0 §33:** Describes a two-step relay where Admin reviews the self-tape before forwarding to the production house.
- **Round 28 Decisions (Item 10):** Specifies direct recruiter review once the audition request is approved.
- **Current Code Decision:** Express backend has unified this into a single endpoint (`PATCH /api/admin/auditions/:id/approve`), which approves the audition request.
- **Product Action Required:** Confirm whether a second post-upload self-tape moderation gate is required or if the current single-approval model is accepted.
